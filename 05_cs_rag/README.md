# 模块⑤ · 客服 AI 自动回复（本地 RAG）

[← 返回作品集首页](../README.md)

把《Q&A-RAG.md》（客服答疑手册）变成一个**可检索、可溯源**的客服知识库，
在看板区块05 里以对话形式提供自动回复。全程**本地运行**：不联网、不调
模型 API、不依赖后端服务，`file://` 双击即可用——包括单文件交付版。

## 文件

| 文件 | 作用 |
|---|---|
| `build_kb.py` | 解析答疑手册 → 切成知识块，写出 `kb.json` |
| `kb.json` | 知识库本体（276 块：274 条问答 + 2 条叙述，14 个分类，约 3.2 万字） |
| `test_rag.js` | 检索回归测试：62 个用例（56 命中 + 6 兜底） |

检索引擎本体在 `02_dashboard/rag.js`（UMD 模块，浏览器与 Node 共用同一份实现），
看板 UI 在 `02_dashboard/index.html` 的区块05。

## 用法

```bat
python 05_cs_rag\build_kb.py          :: 重建知识库（改了手册后跑）
node  05_cs_rag\test_rag.js           :: 跑检索回归测试（-v 看打分明细）
```

## 检索原理（写死在 rag.js，可解释）

1. **切块**：一条 Q&A = 一个知识块（KB-001…）；叙述性内容按章节成块
2. **归一**：玩家口语映射到手调用词（氪金→充值、每天→每日、攻城→沙巴克…），
   查询侧与索引侧走同一套归一；疑问短语（多少钱/什么时候/怎么办…）整段剥离，
   避免跨词边界的噪声 gram 拉低匹配
3. **价格意图归一**：收费 / 要钱 / 花钱 / 付费 / 白嫖 / 零氪 / 收不收费 统一锚到
   「免费」。这一族与「充值」是两件事——前者问门槛，后者问操作与档位；
   早期版本把「付费」映射成「充值」，会把「需要付费吗」带去 VIP 累充条目。
   命中「月卡 / 首充 / 多少钱」这类消费对象时不做该归一。
4. **停用词前移**：多字停用词（这个 / 那个 / 可以 / 你们…）在切 bigram **之前**
   整词剥掉。切完再滤是无效的——「这个游戏」早已切出「个游」，滤掉原词也留不下
   一堆跨词碎片。
5. **分词**：中文 bigram + 英文词/数字（无词典、无分词器，浏览器原生可跑）
6. **打分**：BM25（k1=1.2, b=0.75），问句 token 重复计入，让「问什么」比「答什么」权重高；
   单块内同一词的有效词频截断到 3 —— 不截断的话，答案里把「月卡」提了五遍的那条
   会压过正好在讲月卡售价的那条（这也是「月卡多少钱」曾答成「月卡奖励能补吗」的原因）
7. **长词补归一**：短语剥离后才拼得出来的复合词要再归一一次。
   「装备 怎么 升级」剥成「装备 升级」才拼得上「装备升级 → 强化装备」，
   放在主归一循环里做，中间隔着「怎么」永远拼不上
8. **判定**（五道闸，任一不过即判「知识库没有」）：
   - 覆盖率：问题实词在知识块中的命中比例 ≥ 42%（泛词不计入）
   - 命中数：问题有两个以上实词却只对上其中一个 → 判为只共享了泛概念
   - 分数下限：防止只靠一个弱词命中
   - 区分度：必须命中至少一个高 IDF 词，否则「游戏」这类泛词会误命中
   - 无实词 / 全泛词 → 直接兜底
9. **排序**：覆盖率只当**闸门**，不当排序键。它粒度太粗（分母通常只有 2~5 个词），
   两条知识块同为 1.00 是常态；过闸后统一交给 BM25 分数排序。
   旧版用覆盖率主排序，导致「玩这个游戏花钱吗」被切成四个词、命中三个不相关的，
   覆盖率 0.75 压过真正该答的那条。
10. **回复**：命中 → 返回原文 + 出处（KB 编号 / 分类 / 匹配度）+ 相关条目；
    未命中 → **「当前问题无法回答，请等待人工介入」**

## 实测表现

- 回归测试 62/62 通过（56 个命中全对位，6 个库外问题全部正确兜底）
- 同一问题的 7 种问法全部归位：游戏免费吗 / 收费吗 / 要钱吗 / 下载要钱吗 /
  玩这个游戏花钱吗 / 需要付费吗 / 白嫖能玩吗 → 均命中「游戏是免费的吗」
- 改造前后对照（同一批问句）：「游戏要钱吗」「下载要钱吗」「白嫖能玩吗」由兜底转命中；
  「玩这个游戏花钱吗」由误命中「这个游戏什么时候上线」转为命中「游戏是免费的吗」；
  「需要付费吗」由误命中「VIP 各等级需要累计充值多少」转为命中免不免费
- 已知局限：极短且高度重叠的问法仍可能落到邻近条目（如"月卡怎么买"落到
  「月卡和终身卡哪个更划算」）——同一名词下有多条知识块时，缺一层意图分桶，
  靠 BM25 只能做到"相关"，做不到"对题"

## 内容覆盖（2026-10-19 扩充）

知识库由 115 块扩充到 276 块，正文由 8,889 字扩充到 31,728 字。扩充集中在
客服真实高频、但原手册缺失的四类场景：

| 类别 | 补充方向 |
|---|---|
| 付费与售后 | 退款政策、未成年人充值、代充风险、发票、累充口径 |
| 账号与安全 | 注销流程、二次实名、账号买卖、钓鱼站识别、二级密码 |
| 新手上路 | 首日动线、资源分配、零氪/月卡/小 R 三档打法、常见误区 |
| 玩法细节 | 强化机制、转生重置、红装获取、战力压制、时装属性 |

新增分类「十三、新手引导与成长」「十四、账号安全与防诈骗」——这两类是原手册
完全空白、但真实客服会话里占比最高的部分。

## 与其他模块的关系

- `build_data.py` 把 `kb.json` 并入 `data.js` 的 `kb` 段，看板区块05 直接消费
- 单文件 `作品集.html`（`build_single.py` 打包）内联了 rag.js 与知识库，
  面试官双击即可对话，无需任何环境
- `#cs-问题` 锚点可直达某个问题，如 `index.html#cs-月卡多少钱`
