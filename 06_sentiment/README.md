# 模块⑥ · 舆情监控（模拟语料）

[← 返回作品集首页](../README.md)

监控口径的完整演示：论坛 + QQ 群双渠道舆情流、情绪趋势、话题分布、P0/P1 分级预警
与处置动作。**不做真实采集**——语料由程序按事件脚本生成，全部标注为模拟数据，
仅供展示"如果接了真数据，这套分析怎么跑"。

## 为什么不接真数据

| 真实路径 | 结论 |
|---|---|
| 论坛抓取 | 可行但要按站点写适配器，且受登录态/反爬约束，作品集演示不稳定 |
| QQ 群实时消息 | 没有开放接口；本地客户端 hook（OneBot 类）有封号风险，不适合随作品集分发 |
| 第三方舆情 API | 要钱，且演示环境断网 |

所以采集层被替换成**事件脚本 + 语料生成器**：真实感来自渠道形态差异（群聊碎片 /
论坛长帖）、时间分布（事件围绕峰值聚集）和事件走向（爆发 → 回应 → 回落），
而不是把假话写得更像真的。页面副标题里明确标注了这一点。

## 文件

| 文件 | 作用 |
|---|---|
| `gen_sentiment.py` | 语料生成器：20 个事件脚本 → 约 780 条帖子，固定种子可复现 |
| `sentiment.json` | 生成结果（约 210 KB），由 `build_data.py` 读进看板 |

## 事件脚本（20 个，对齐前五个区块的叙事）

时间窗为开服 5 天（10-13 ~ 10-17），与 `data/game.db` 的数据范围一致：

- **P0 ×4**：开服排队炸服、充值未到账、外挂脚本举报、定向抽奖概率质疑（对齐区块03
  `ACT-DRAW-001` 10-17 上线）
- **P1 ×9**：新手引导卡死、首充规则争议、职业平衡、排行榜太卷（对齐 `ACT-RANK-001`）、
  老带新链接失效、抽奖券太少、周末收益 UP 未生效（对齐 `ACT-SPEC-002` 第 1 期）、
  终身礼包定价争议（对齐 `ACT-GIFT-006` 10-20 预告）、晚间卡顿
- **P2 ×7**：月卡讨论、回归礼包、拍卖行手续费、客服时效、攻略分享（正面）、公会招募、广告刷屏

其中 4 个 P0 事件标记了**跨渠道共振**（论坛与群同时出现），预警卡上会标注。

## 生成口径

- 情绪分：事件基调 ± 噪声（σ=0.3），约 26% 的发言判为中性附和；±0.2 为正/负分界
- 时间分布：68% 的条目聚在事件峰值附近（正态），其余均匀铺满区间
- 群消息避让最近 10 条重复；`@管理` 只出现在求助/投诉语上
- 分桶：6 小时一桶（约 20 桶），供趋势图与"按时段筛选"
- 预警：每个 P0/P1 事件一条，含触发规则、条数、处置动作、样本帖

## 修改语料

改 `gen_sentiment.py` 里的 `EVENTS`（加事件 / 改话术 / 调条数），然后：

```
python 06_sentiment/gen_sentiment.py
python 02_dashboard/build_data.py
python 02_dashboard/build_single.py     # 如需更新单文件版
```

`--stat` 只看统计不写文件。随机种子固定为 `SEED = 20261017`，重跑结果一致。

## 如果以后要接真数据

`sentiment.json` 的 post 结构就是采集层要吐的格式：
`{post_id, ch, sub, title, text, author, at, replies, sentiment, topic, level, event_id, parent_id, cross}`。
按这个 schema 写论坛适配器或 OneBot 适配器，替换掉 `gen_sentiment.py` 即可，
分析聚合与看板都不用动。
